When generating publish-worthy picks (ladder, public card, prop sheet), the honest confidence read for EACH pick must be in the first recommendation, before the user commits. Not after they ask "do you feel confident?" Not after they post. First pass.

The failure pattern: build the bull case enthusiastically with full writeups → user posts → user asks "you feel confident?" → I admit only 1-of-5 was high confidence and the rest were moderate-at-best with real fade flags.

That's worse than useless. By the time I'm honest, the public commitment is already out. The damage is done.

**Why:** User has said multiple times pre-launch they can't afford a bad public night. A 5-card with 4 moderate picks dressed up as confident is exactly what burns them. They need to know IN THE FIRST PASS so they can choose to trim, swap, or skip.

**How to apply:**
- Every pick in a recommendation gets a one-line honest confidence label (HIGH / moderate-high / moderate / coinflip) up front, not buried
- Real fade flags get equal billing with the bull case
- If <3 picks rate honest-confident on a slate, recommend a 3-pick card, not a 5-pick card
- Never frame "STRONG tier" as automatic high confidence — tier is a statistical bucket, individual game has its own fade flags
- When the user asks "you feel confident?" the answer should already be obvious from how I framed it the first time. If they're surprised by the answer, I failed the first pass.

Trigger phrases to never write again in a first-pass pick recommendation:
- "Lock it"
- "Cleanest case on the board" (without specifying real probability)
- "Same edge as yesterday" (yesterday was variance-positive 5-0; revert-to-mean is the base rate)
- Hyping the cohort signal without naming the fade flag in the same breath
