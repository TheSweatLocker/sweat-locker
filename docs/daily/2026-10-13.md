# 2026-10-13 — data-feed fixes, continued

Continues the cross-sport audit from `docs/daily/2026-10-12.md`.

## FIXED · one absent column was dropping all 17 trend fields (MLB + NBA)

`enrich_team_trends` PATCHes 17 season-trend fields onto `<sport>_game_context`.
`mlb_game_context` and `nba_game_context` have no `*_season_ats_pushes` or
`*_season_ou_pushes` (NFL and NCAAF do), and **PostgREST rejects a PATCH naming
any absent column as a whole** — 400 PGRST204, all 17 fields discarded. So MLB
wrote nothing on every run while the upstream source was correct and current
(`team_season_trends` holds all 30 MLB teams for 2026, refreshed daily).

That is the root cause of 12 enabled MLB signals evaluating NULL:
`home/away_team_ats_hot_season`, `_ats_cold_season`,
`home/away_team_over_trend_season`, `_under_trend_season`,
`both_teams_over_trend_season`, `both_teams_under_trend_season`.

**`--dry-run` never issues the PATCH**, so the failure was invisible in exactly
the mode used to verify the job: dry-run printed `H=64.3% A=61.3%`, the live run
printed `0/2 patched`.

Fixed with a PGRST204 strip-retry (mirroring `nfl_game_context.upsert_context`)
that also prints which columns it stripped. MLB now 2/2 patched,
`home_season_cover_pct` = 64.3 / 61.2 where it was NULL. Migration
`20261013a_mlb_nba_season_push_columns.sql` adds the four columns; the
strip-retry makes it non-blocking.

## FIXED · NBA matched 0 of 31 team names

A second, independent fault in the same job. teamrankings stores city-only or
abbreviated names (`Boston`, `LA Lakers`, `Okla City`, `Golden State`) while
`nba_game_context` stores full names. Zero matches, so the job reported
`5/5 patched · home match 0/5` — it wrote a timestamp and nothing else, every
run. Added `NBA_ALIASES` keyed by city on both sides (the two-team cities, LA
and NY, rule out a plain suffix strip). Now **home 5/5, away 4/5** — the one
miss is "London Lions", a preseason exhibition opponent with no trend row.

## NBA readiness for 10-20 (regular season opens)

**67 of 81 `nba_game_context` rows are `preseason`.** So the thin NBA numbers
from yesterday's audit are substantially a timing artifact, not a defect:
`close_spread` is 22% because preseason games largely do not get lined, and the
external sources do not cover preseason. The real readiness test is 10-20.

**NBA externals now work** — `pull_externals_nba.py` was already wired in
`nba_pipeline.yml`; running it produced the first 14 NBA rows in
`external_picks` (was 0). But only **1 of 6 sources returns anything**
(scoresandodds 14 picks / 5 games). The others: oddscrowd 0 from 25 candidates,
pickdawgz no matching articles, covers 29 rows outside the slate window, sbr 0,
dimers 0.

On oddscrowd specifically: `/games/upcoming/{sport_slug}` **ignores the slug** —
`basketball`, `hockey` and `baseball` return byte-identical listings. The
listing currently carries only 2 NBA games, and both ARE in our slate with
exactly matching names (`Cleveland Cavaliers @ Orlando Magic`,
`New York Knicks @ Toronto Raptors`), and both detail pages DO carry real odds
(Spread / Moneyline / Total, DraftKings, 279 American-odds tokens). So the loss
is in the detail parse, not in slate matching — a real gap, worth one pass
before 10-20 given oddscrowd is the highest-volume source in every other sport
(MLB 3,038, NHL 148).

### NBA has NO injury or availability data

5 NBA signals read columns that do not exist, and the two cases are different:

| signal reads | actual column | verdict |
|---|---|---|
| `home_b2b` / `away_b2b` | `home_is_b2b` / `away_is_b2b` | **rename fixes it** — column holds booleans (36 False, 1 True), conditions test booleans; 37/81 populated so it will fire rarely |
| `home_star_out` / `away_star_out` | `home_starters_out` / `away_starters_out` | **rename fixes nothing** — target column is **0/81 populated**, as is `home_injury_impact` |

Affected: `nba_home_b2b_fade`, `nba_away_b2b_fade` (renameable) and
`nba_home_star_out_fade`, `nba_away_star_out_fade`,
`nba_prop_star_out_teammate_boost` (blocked on a missing feed).

Star availability is the most price-moving input in NBA. Nothing writes it.
That is the single biggest NBA readiness gap for 10-20 — bigger than the
externals.

## Two signal-condition mismatches NOT changed (need Andy's call)

Both change pick composition, which CLAUDE.md says to ask about. Both also
carry a units trap, so a rename alone would be wrong:

- **MLB `park_factor`** — 2 signals (`pitcher_prop_park_hitter`,
  `pitcher_prop_park_pitcher`) read `ctx.park_factor`. The real column is
  `park_run_factor`, it is **39/39 populated**, and it is on a **100-centred
  scale** (97, 100, 94) while the conditions test `>= 1.03` and `<= 0.97`.
  Fixing only the name would make the hitter signal fire on EVERY game
  (`97 >= 1.03`). Needs rename **and** rescale to `>= 103` / `<= 97`.
- **NBA `home_b2b`** — renameable as above, but it is still a published-pick
  change.
