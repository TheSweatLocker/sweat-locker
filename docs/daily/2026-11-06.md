## 3. 🚨 R166 FIXED — and there were THREE defects under it, not one

### (a) Three writers, one UTC date

`resolve_ncaab_results`, `ncaab_backfill_results` and `ncaab_odds_pull` each
held an identical copy of:

```python
dt = datetime.fromisoformat(commence.replace('Z', '+00:00'))
game_date = dt.date().isoformat()
game_id = f'ncaab_{dt.strftime("%Y%m%d")}_{away}_{home}'
```

No ET conversion anywhere. A 7pm ET tip is 00:00 UTC the next day, and for
NCAAB that is most of the slate, so the game was filed a day late in **both**
fields. `grade_public_receipts` bridges a receipt to its result on
`(game_date, away_team, home_team)` — the date is **in the join key** — so
every such receipt was permanently ungradeable.

Derivation now lives once, in `sweat_dates.et_and_utc_stamps()`, via zoneinfo
(not a hardcoded −4; today is EST and −4 would be wrong right now). Three
copies of one derivation is the same shape as
`feedback_each_scraper_invented_its_own_season`.

### (b) 🚨 `fetch_existing` could NEVER match anything

The dry run still reported `existing rows matched: 0/165` after the date fix,
while a direct probe for the very first id returned the row. Two defects, the
second hiding the first:

1. it chunked at **100 ids**, building a ~4KB URL that this stack silently
   **truncates** — measured: 25 ids / 1,028 chars → HTTP 200, 50 ids / 2,022
   chars → `PGRST100 "unexpected end of input expecting "," or ")""`; and
2. `if r.status_code != 200: continue` **swallowed that 400**, so the function
   returned `{}` and every game looked NEW.

So the resolver never PATCHED a row in its life — it only ever inserted. That
is why 11-03 held 144 rows. A silent `continue` on a non-200 turns a wiring
error into a finding (`feedback_zero_rows_is_a_wiring_error`). Now chunked at
20 and it **raises** on an unreadable lookup, because "could not read" must
never read as "not stored yet" — that sends every game down the INSERT path.

The same flaw was in the helper I wrote an hour earlier. Fixed there too.

### (c) The migration had to be legacy-aware or it would duplicate

Every stored row is keyed by the UTC id. Writing the new ET id would not
conflict with anything — it would **INSERT a second row per game**: 165
duplicates on one date, in the table that grades the record. So
`ncaab_result_ids.reconcile()` asks, before every write, whether the game is
already stored under its legacy id and points the payload at **that** row.
Wired into all three writers.

## 5. The Fade: the spread fade does not exist. The TOTALS fade replicates.

### The contradiction is resolved, and the 11-02 result was the artefact

`public_splits_archive.pick_side` carries two conventions in one column —
the **public** side on oddscrowd rows, the **sharp** side on the fr/ftp/cz
rows. Three of four feeds index the sharp side in a table named *public*.
That one ambiguity produced two opposite answers to the same question five
days apart.

Re-measured off `public_splits_v2`, whose `side` is an explicit
HOME/AWAY/OVER/UNDER and whose two sides sum to 100 in **99%+** of
two-sided groups, with the public side **derived from the ticket numbers**
so no label can invert it — and against a **side-matched blanket control**
computed over the same games:

| market | n | fade | control | selection |
|---|---|---|---|---|
| spread | 2,751 | 50.16% | 50.16% | **+0.01pp (+0.01 SE)** |
| ml | 2,282 | 33.52% | 46.28% | −12.76pp (−12.19 SE) |
| total | 2,806 | 50.89% | 49.71% | +1.19pp (+1.26 SE) |

The spread fade is **exactly** the blanket base rate of whichever side it
happened to take. Zero selection value. Its bands run the wrong way too
(50-60% public +2.80pp → 80-100% **−3.74pp**). The 11-02 archive study was
a convention artefact.

**NHL spreads are worse than nothing: −8.15pp (−3.70 SE) on n=514.** The
public is *right* on puck lines. That is an anti-signal, not a fade.

ML is a confound, not a signal: fading the public on a moneyline just means
taking dogs, and it loses 12.76pp to the side-matched control.

### The one thing that survives — and it replicates

**TOTALS, public ticket share 60-80%:**

| | n | fade | control | selection |
|---|---|---|---|---|
| **whole band** | **1,253** | **54.43%** | 49.77% | **+4.66pp (+3.30 SE)** |
| early half | 626 | 55.91% | 49.80% | +6.11pp (+3.06 SE) |
| late half | 627 | 52.95% | 49.73% | +3.22pp (+1.61 SE) |

Split on the band's own median game date (2026-10-10). **Both halves
positive**, and the early half alone clears 1.96 SE.

By sport, every one positive:

| sport | n | selection |
|---|---|---|
| NCAAF | 832 | **+4.20pp (+2.42 SE)** |
| NCAAB | 132 | +6.67pp (+1.53 SE) |
| NFL | 160 | +4.57pp (+1.16 SE) |
| NHL | 89 | +4.54pp (+0.86 SE) |

Five independent sports, five positive signs. And it **inverts above 80%**

This independently corroborates `project_sharp_vs_public_measured_1102`,
