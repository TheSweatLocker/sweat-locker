### game_time_et is UTC, so an unread NCAAB game could never go CRITICAL

`_READ_KICKOFF_COL` carried `('game_time_et', False)` because the name says
ET. Conservative instinct, wrong answer: with `is_utc` False,
`check_reads_missing_near_kickoff` can only ever raise WARNING for NCAAB,
never CRITICAL, on the sport with the most games.

Measured on all 506 rows instead of reasoned from the name: **506 of 506 end
in `+00:00`**. Read as UTC, tip hours are 19:00 x197, 20:00 x96, 21:00 x58,
18:00 x37, 22:00 x35 - a textbook slate. Read as already-ET, 197 games tip at
00:00 and 96 at 01:00. The name is wrong; the data is UTC, and
`app/index.tsx` (~3447) has always consumed it as a commence_time. This
watchdog was the only reader treating it as local.

Not renaming the column - two consumers and a data migration to buy a better
name is a worse trade than documenting it where it was misread.

### Line movement: measurable now, and no edge

`line_history` has 446,782 NCAAB rows keyed on the **results** game_id scheme
(`ncaab_20261101_Villanova_Notre_Dame`), not the context hash - which is why
an earlier join matched 0 of 71. It starts 2026-10-28, so it cannot backfill
anything older, but it gives true open->close movement from here: 272 graded
games, median **49 captures** each, 204 where the number moved >=0.5.

No edge. Follow the move 48.0-49.5%, fade it 50.5-52.0%, the always-HOME
control beats both at 52.6%, and `corr(move, residual vs close)` is **+0.03**
on n=204. The move carries no information beyond the closing line, which is
what an efficient market looks like.
