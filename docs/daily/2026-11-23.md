## 1. The test I shipped yesterday has been failing in CI since the hour it landed

`test_card_self_contradiction.py` reported **exit 1 after 0s on every
`daily_card` run** from 2026-11-22 onward — 6 runs today alone. Zero seconds is
not an assertion failure, it is an import crash.

`consistency_watchdog.py:45` reads `SUPABASE_URL` at **module** level, falling
back to `mlb_pipeline/.env`, which exists locally and does not exist on a
runner. My workflow step set only `PYTHONIOENCODING`. So the test passed 12/12
here and raised `KeyError` there, and `--detector` faithfully recorded a
finding nobody had written.

The fix is **not** to hand a pure-function test the production secrets. These
twelve assertions touch no table. `os.environ.setdefault` with placeholders
keeps that true, makes the module importable anywhere, and means an accidental
request fails on a dead host instead of reaching the real database. Verified
the way CI sees it — `.env` moved aside, every `SUPABASE_*` var stripped:
12/12, exit 0. `check_ci_python_compat.py`: 972 files, 0 findings.

Lesson, and it is the second time in four days: **a guard's own wiring needs a
run under the conditions it will run in.** `--detector` did its job — the card
kept shipping and the failure was recorded — which is exactly why it sat for a
day without anyone noticing.

### What this means for tuning

1. **Re-measure every signal on its own side, not on the games we picked.**
   Until the registry's `hit_rate` is computed off a pick-independent sample,
   every weight derived from it is partly our own win rate. This is the root
   fix and everything else is downstream of it.
2. **Schedule the enforcement that already exists**:
   `apply_signal_weight_discipline.py` (unscheduled),
   `audit_home_away_signal_bias.py` (unscheduled), and
   `cap_unmeasured_signal_weight.py` in the four pipelines that lack it. Teach
   the cap to read `tier`, not just `sample_n`.
3. **Require a direction-only control before any weight.** A signal that fires
   on one side only must beat that side's base rate, and a near-100%-one-sided
   signal should be labelled a direction bet, not a signal.
4. **Do not tune NBA or NHL yet — instrument them first.** 213 and 327
   attribution rows is not a basis for re-weighting. Extend
   `signal_attribution_snapshot.py` coverage, then re-measure.
5. **Attach the price to `signal_attribution`.** It carries `close_line` but no
   odds, so no signal can currently be measured against break-even — the same
   `close_price_american` gap as section 4.
