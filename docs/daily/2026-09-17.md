## Publish lock system (2026-09-17 late PM — brand-integrity fix)

Andy directive: "prime prop integrity issue — comes off as we're
cherry picking. This is brand-killing. Needs process that overwrite
in the middle of day to stop." + "and this needs to be sport
universal." Full docs in `docs/TECHNICAL_REFERENCE.md` Section 10.

**Root cause of the yo-yo:** `generate_props.py` uses
`Prefer: resolution=merge-duplicates` — that's a row-level REPLACE
on conflict, NOT a field-level merge. LR-override state
(`_lr_p_hit`, `_lr_tier_raw`) gets wiped when generate_props re-runs.
`backfill_prop_lookback.py` restores the LR promotion, but only if
it runs AFTER. Daily workflow chains them right. Ad-hoc `--force`
reruns broke the order — that's what happened to Seth Lugo today
(PRIME 79 all morning, wiped to SKIP 20 by my noon --force run,
would have been excluded from tonight's PRIME record).

**Three-layer fix:**

1) **`publish_lock` table** (migration `20260917e`) — universal
   `(sport, market, source_id)` → tier_at_publish + conviction_at_publish
   snapshot. Sport-universal, first-publisher-wins. Grader
   (`compute_surface_records.py`) JOINs on it, prefers locked tier.

2) **DB trigger freeze-on-lock** (migration `20260917f`) — any
   UPDATE to `tier` or `conviction` on mlb/nfl_pipeline_props checks
   publish_lock. If a lock exists, silently rewrites NEW.tier =
   locked. Composers CAN'T flip a locked pick. Live tier = locked
   tier = one truth.

3) **generate_props auto-chain** — after `run()` completes,
   subprocess-fires `backfill_prop_lookback.py --sport MLB --date $today`
   in same invocation. Kills the yo-yo trigger at source.

**Wired composers (write locks at publish):**
- `generate_sweat_card.py` — iterates card.top_8 pre-POST
- `generate_sharp_card.py` — iterates items pre-POST; added
  `id` + `conviction` + `game_id` to composed dicts
- `jerry_anchor_potd.py` — winner_read at final upsert
- `generate_prop_jerry_synthesis.py` — after successful jerry_read write

**Backfill for today:** `python mlb_pipeline/backfill_publish_locks.py`
— walks jerry_cache surfaces + prop_jerry_reads, locks each pick at
current-surface tier. Ran 9/17 evening, 167 locks written. Lugo
outs_under confirmed locked at PRIME 79 despite live SKIP.

**Andy 9/17 policy call:** legacy records NOT retroactively
corrected. "I don't even know if I want to dig into [historical
damage]." Publish_lock only affects rows locked from this date
forward. Old records stay as-is; accept the uncertainty. Forward
records honest.
