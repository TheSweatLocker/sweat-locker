## §1 — The guard I shipped yesterday killed every Sweat Card run for 21 hours

`daily_card` ran 8 times on 11-21 and every run lasted **6–12 seconds**. Runs

Step 6 is the guard I added yesterday to catch a 3.12-only f-string:

```
python -m compileall -q -x '_legacy|__pycache__' mlb_pipeline
```

### Root cause

Installed CPython **3.11.18** — the exact version CI pins, visible in the
runner paths — via `uv python install 3.11`, and compiled all 969 tracked
files. Exactly one fails:

```
mlb_pipeline/grade_money_flow.py:471   f-string: f-string: unmatched '['
      f'{f"{best["w"]}-{best["l"]}-{best["p"]}":>12}'
```

An outer f-string delimited with `'` holding an **inner** one delimited with
`"`, whose dict keys reuse that `"`. Legal from 3.12 (PEP 701), a hard
SyntaxError on 3.11. The doubled `f-string: f-string:` prefix is the
tokeniser saying the collision is one level down.

Mine, from **6f2d8aef on 10-20 — a month old**. The file is in **no
workflow**: nothing runs it, nothing imports it (`grade_money_flow_shadow.py`
is the one `mlb_pipeline.yml` runs; my first grep matched the prefix and I
nearly reported the wrong thing). It was inert for a month.

### The lesson: the guard's blast radius exceeded what it guarded

Byte-compiling the directory made one dormant line in an unused file a hard
dependency of every surface the job produces. A gate must fail on what the
job cannot do without, and 969 files is not that — this job runs 30 scripts,
93 files with their imports.

## §2 — The author-side checker had three defects, which is why it said "clean"

`check_ci_python_compat.py`, written yesterday as the counterpart to the gate,
reported the tree clean while 3.11 rejected it.

1. **It kept ONE delimiter, captured at nesting depth 1.** A nested
   f-string's own quote was never the comparison basis — exactly this case.
   Now a stack, compared against every open frame. Proven by re-running the
   fixed scanner against the committed file: **3 findings on line 471.**
2. **`t.string[:1]` read the PREFIX** of a nested `r"x"` / `rb'x'` as its
   delimiter, so those collisions matched nothing. Now strips prefixes.
3. **Its file set was narrower than the gate's.** It skipped every `_*.py` on
   the CLAUDE.md note that they are gitignored scratch — but **133 of them
   are committed** (`.gitignore:91` post-dates them, and tracked beats
   ignored), so CI parses files the checker never opened. It now takes the
   tracked list from `git ls-files`: 969 files, exactly what the gate
   compiles.

A file set *narrower* than the gate's misses the real thing; *wider* cries
wolf — the old `os.walk` saw 2080 files here and flagged an untracked,
gitignored scratch file CI will never see. The criterion is tracked-or-not:
not the filename, and not the ignore rule.

13/13 self-tests, and the two "does 3.11 really reject this" controls now run
against a real 3.11 and print **SKIP**, not PASS, when no such interpreter is
available.
