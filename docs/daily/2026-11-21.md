### Root cause

Installed CPython **3.11.18** — the exact version CI pins, visible in the
runner paths — via `uv python install 3.11`, and compiled all 969 tracked
files. Exactly one fails:

```
mlb_pipeline/grade_money_flow.py:471   f-string: f-string: unmatched '['
      f'{f"{best["w"]}-{best["l"]}-{best["p"]}":>12}'
```

An outer f-string delimited with `'` holding an **inner** one delimited with
`"`, whose dict keys reuse that `"`. Legal from 3.12 (PEP 701), a hard
SyntaxError on 3.11. The doubled `f-string: f-string:` prefix is the
tokeniser saying the collision is one level down.

Mine, from **6f2d8aef on 10-20 — a month old**. The file is in **no
workflow**: nothing runs it, nothing imports it (`grade_money_flow_shadow.py`
is the one `mlb_pipeline.yml` runs; my first grep matched the prefix and I
nearly reported the wrong thing). It was inert for a month.

### The lesson: the guard's blast radius exceeded what it guarded

Byte-compiling the directory made one dormant line in an unused file a hard
dependency of every surface the job produces. A gate must fail on what the
job cannot do without, and 969 files is not that — this job runs 30 scripts,
93 files with their imports.

## §2 — The author-side checker had three defects, which is why it said "clean"

`check_ci_python_compat.py`, written yesterday as the counterpart to the gate,
reported the tree clean while 3.11 rejected it.

1. **It kept ONE delimiter, captured at nesting depth 1.** A nested
   f-string's own quote was never the comparison basis — exactly this case.
   Now a stack, compared against every open frame. Proven by re-running the
   fixed scanner against the committed file: **3 findings on line 471.**
2. **`t.string[:1]` read the PREFIX** of a nested `r"x"` / `rb'x'` as its
   delimiter, so those collisions matched nothing. Now strips prefixes.
3. **Its file set was narrower than the gate's.** It skipped every `_*.py` on
   the CLAUDE.md note that they are gitignored scratch — but **133 of them
   are committed** (`.gitignore:91` post-dates them, and tracked beats
   ignored), so CI parses files the checker never opened. It now takes the
   tracked list from `git ls-files`: 969 files, exactly what the gate
   compiles.

A file set *narrower* than the gate's misses the real thing; *wider* cries
wolf — the old `os.walk` saw 2080 files here and flagged an untracked,
gitignored scratch file CI will never see. The criterion is tracked-or-not:
not the filename, and not the ignore rule.

13/13 self-tests, and the two "does 3.11 really reject this" controls now run
against a real 3.11 and print **SKIP**, not PASS, when no such interpreter is
available.

## §5 — A gap of exactly 2x the magnitude is a SIGN, not a market move

Andy: "do it" — on `locked_pick_line_drift`, the live CRITICAL.

```
🚨 12 locked spread pick(s) carry a line the market has moved off,
   5 of them unbettable on a game inside 72h
```

Two of the five:

```
NCAAF Arkansas @ Texas   published +20.5, market -20.5  (+41.0)
NCAAF Iowa @ Illinois    published  +8.5, market  -8.5  (+17.0)
```

Same absolute value on both sides, gap exactly 2x the magnitude. No market
moves 41 points on a 20.5 spread. Measured at the number we actually
published, **both gaps are +0.0** — the picks matched the board to the
half-point.

### First suspicion was wrong, and the moneyline said so

I suspected the detector's NCAAF orientation sign. It is correct: on all six
drifted NCAAF games `close_spread` agrees with `close_home_ml` about who is
favoured, so positive really is the home handicap. The detector's measured
`_HOME_HCAP_SIGN` map stands.

### Root cause — the flip rewrote the label and left the line

`defensive_gates.apply_oc_flip_gate` (the OddsCrowd dissent fade) flips
`side`, `label` and `tier`. It computed the correctly-signed line **inside
the label f-string** and threw the value away:

```python
line = float(cs) if new_side == 'HOME' else -float(cs)
new_label = f"{home if new_side == 'HOME' else away} {line:+g}"
...
pp['side']  = new_side
pp['label'] = new_label
pp['tier']  = new_tier          # <- pp['line'] never written
```

So a flip from the dog to the favourite left:

```
label "Texas -20.5"   line +20.5
```

**48 of 52 `_oc_flipped` NCAAF spread picks** since 08-25, back to week 1.
NFL 1 flip, NBA 2, NHL/NCAAB 0 — NCAAF is where this gate fires.

A second defect in the same three lines: `float(cs)` is **sport-blind**, and
NFL stores `close_spread` as the opposite convention to NCAAF/NBA
(`repair_spread_labels.CFG` and `watchdogs._HOME_HCAP_SIGN` both say so). On
NFL the label's sign was backwards too — invisible so far only because the
gate has fired on one NFL game all season.

### The record was never wrong, and that was MEASURED

The tempting conclusion was 37 corrupted receipts. That number came from
comparing each receipt's line against the *context row's* label — but
several of those games carry receipts on **both** sides from different
surfaces, so a sign difference there is a different pick, not an error. The
honest test is self-contained: does a receipt's own `pick_label` agree with
its own `pick_line`?

**23 of 2,088** spread receipts disagree (19 NCAAF, 4 MLB, 22 of them
`game_read`, mostly one batch on 09-12). I re-graded all of them from final
scores:

| | |
|---|---|
| graded receipts matching the **published label** | **16 of 16** |
| graded at the wrong-signed line | **0** |

including six that would have settled the other way had the line been used
(Clemson -19.5, Oregon -23.5, LSU -35.5, Tulsa -11.5, Alabama -17.5,
Dodgers -1.5). **Graders settle off the label.** So this blinded a detector;
it never cost a unit. `public_receipts.pick_line` is immutable by trigger
and was left alone — it is inert for grading, and rewriting frozen receipts
is a records decision, not a repair.

### Fixes

1. **`defensive_gates.apply_oc_flip_gate`** now negates the line it holds
   (`new_line = -float(pp['line'])`) and builds the label from that same
   number, so the two cannot diverge. Negating our own line is what both
   other flip writers already do (`flip_football_spreads.py` `new_line =
   -ours`; `generate_sharp_card._flip_short_spread` `new_line = -line`,
   whose docstring documents the house convention: *`primary_play.line` is
   signed from the picked side's point of view*). It also needs **no**
   per-sport orientation sign, which is what removes the NFL defect. An `rl`
   with no line gets a `TEAM RL` label rather than a guessed number —
   `repair_spread_labels.py` already owns that case. 17/17 cases, both
   directions, including an NFL control and a "no dissent → untouched"
   control.
2. **`repair_flipped_spread_line_sign.py`** (new) re-signs stored rows to
   agree with the published label. Side, market, tier and **magnitude**
   untouched. A magnitude difference is reported and never repaired —
   |label| != |line| means they disagree about the bet, not its orientation,
   and guessing which is right is how a repair becomes a repick. 14/14
   self-tests. Applied: **48 repaired, 0 failed** (each confirmed by
   readback, so no lock trigger silently reverted one), 999 already agreed,
   1 magnitude difference left standing (Connecticut +6.5 vs line 7.5,
   11-07). Re-run is a clean no-op.
3. **`watchdogs.check_locked_pick_line_drift`** now measures against the
   number we published and reports a same-magnitude sign disagreement **as a
   sign defect**, not as drift — so no future writer can turn this class of
   bug into a phantom 41-point market move again. (`re` was not imported in
   `watchdogs.py`; the first version of this guard would have been a
   NameError inside the check — [[feedback_swallowed_nameerror_is_a_false_condition]].)
4. Same check: **`hrs <= 72` had no lower bound**, so a game that already
   kicked off counted as imminent — 2 of 3 CRITICALs were games 1 and 3
   hours PAST kickoff. Still a CRITICAL (a number nobody can bet is on
   screen either way) but counted and labelled separately, because burying
   the actionable one in a single total is how it gets read as noise.
