## 4. NBA lines — and a sign I put in backwards  (`1f537be6`)

At 05:00 ET all 15 NBA context rows for today had NULL spread *and* total,
while `line_history` held 19,094 NBA quotes covering all 15 games (newest
10:26Z, 15/15 joining on `game_id`). `nba_game_context.py` fills from a
**live Odds API call at run time**, so lines only appear when the pipeline
runs:

| stage | lands (UTC) | ET |
|---|---|---|
| daily_card composes + locks the card | 09:18–11:41 | 04:18–06:41 |
| Sweat Card HARD LOCK | — | **12:00** |
| nba_pipeline fills ctx + reads | 16:53–17:52 | 11:53–12:52 |

Six hours after the card was built. Measured cron delay: **3.0–9.0h** over 23
runs — no single cron can hit that, so `pregame_lines.yml` runs 2-hourly and
fills **NULLs only**.

Also checked the other suspect first: the percentile tier bars **are** live
for NBA/NHL, so the 10-30 tier-bar defect is fixed and isn't the blocker.

**I broke it live.** The fill stored `hl if hl < 0 else -hl` — i.e.
`-abs(hl)` — forcing the spread negative on every game, so a home dog at
+5.5 became −5.5. It was **correct on 12 of 15** games, which is how a
magnitude bug survives review. What exposed it was asking a *second* source
the same question: the moneyline said home was the dog on three games where
the spread said favoured. Repaired (+5.5, +4.5, +4.5); detector now 0 for
both sports.

Convention pinned three ways before touching the sign: `close_spread` = the
home-side line as posted (NBA 45 exact of 89, 2 for the negation; NHL 13 of
14), agreeing with `_HOME_HANDICAP_SIGN['NBA'] = 1.0` and the
`corr = −0.517, n=2,449` already in that file's header.

Guards: the fill refuses a row whose spread and moneyline name different
favourites; the repair requires ≥4pp implied gap before treating a
disagreement as evidence (a −110/−110 game has no favourite). That dropped
two false positives and showed the 10-28 run did no detectable damage.

## 6. NCAAB published its projection as the market's number  (`bc98d84c`)

16 of 57 NCAAB receipts carried lines like `Under 157.83333333333334`.
Measured before shipping any guard: **17 of 27,432 receipts (0.06%)** are not
a multiple of 0.5 — 16 NCAAB totals, 1 MLB. Rule added to
`receipt_invariants.check_row`, the chokepoint both the live `capture()` and
the direct-POSTing backfill screen through. **Refuses on every surface**,
stricter than the missing-price rule, because a read with no price is still
gradeable W/L while a fabricated line describes no real bet.

Voided the 16 stored rows; the 17th is **graded** (MLB `Over 8.7`, WIN) and
left alone.

**Deliberately not fixed:** 41 NCAAB receipts remain priceless. The blunt
guard would refuse 13–18% in *every* sport (255 rows, many graded), and rule
(1) already WARNs them on purpose. Root cause is upstream —
`ncaab_game_context` close lines are NULL on 63 of 138 rows (46%) — but NCAAB
**cannot** join `line_history` yet: it stores `ncaab_20261103_Milwaukee_USC`
with matchup `Milwaukee Panthers @ USC Trojans`. Bridging needs a team-name
alias layer, and guessing one is how the NCAAF composed `game_id` produced 21
duplicate rows with one home/away **inverted**.
