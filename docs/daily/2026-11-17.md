### The mechanism

`ncaab_game_context.py` writes a PRELIMINARY `primary_play` — the
cap/floor shape (`_total_cap`, `signal_floor`, `_ml_cap`), with **no
`conviction`, no `score`, no `_engine`**. The 4-lens resolver is what
replaces it with the real pick. Resolver stamp coverage on ctx rows:

```
11-04..11-06  100%        11-15  11 of 29
11-11         26 of 42    11-16  10 of 20
11-14         32 of 51    11-17   0 of 43   <<< DARK
```

`sync_jerry_reads_from_ctx` then reads `pp['conviction']` (line ~409) and
writes `None`.

### Why the resolver never ran

`run()` resolved exactly `et_today()`. The `23 20 * * *` card_only cron is
set for 4pm ET; **GitHub ran it at 03:01Z = 10:01pm ET on the 16th**. At
that hour `et_today()` is still **11-16**, whose 23 games had all tipped,
so the started-game guard refused every one:

```
23 game(s) already tipped - pick left as published
0 rows resolved; tier breakdown: {}
```

Exit 0. Nothing written. And the step was a bare `python` call under
`continue-on-error: true`, so **nothing recorded it either.** Meanwhile
`ncaab_game_context.py` had already written the 11-17 board, which kept
its preliminary pick.

The 11-03 note in `run()` is right that UTC was wrong and ET was better.
But **a single date from any clock cannot work here**, because the
resolver and the context builder do not work the same date — the context
builder follows the odds feed *forward*.

**Fixed**: with no `--game-date`, resolve the whole `ET today .. +1`
window. Safe *because of* the started-game guard — a tipped game is
refused, so a wider window can only reach games that have not started.
Validated at the failing hour by pinning `et_today()` to 11-16:
