## The NFL Pipeline Weekly failure: a false failure

Run **38503899770**, 2026-10-14T03:03 UTC. `workflow_heartbeat` had the step
and the return code: `refresh_nfl_team_features.py`, rc=1, 29s.

**The write succeeded. The verification was wrong.** All 193 rows got
`features_computed_at = 2026-10-14` (UTC). The check compared

```python
str(x.get('features_computed_at'))[:10] == et_today()
```

and `et_today()` returned **2026-10-13**, because the stamp is written in UTC
(`dt.datetime.now(dt.timezone.utc)`) and compared against an **Eastern**
date. Between 00:00 and ~04:00 UTC the two disagree by a calendar day and
every row looks unstamped → `stamped=0` → `return 1`.

The `0 */6 * * *` cron puts one run in that window every night, which is why
it failed nightly and passed during the day — the shape that reads as flaky
rather than wrong. The run fired at 02:59 UTC = 22:59 ET.

**Fixed** by comparing against the run's own timestamp with 2h slack instead
of a calendar day. A date comparison is the wrong instrument regardless of
which timezone wins — a job straddling midnight would fail it too. Verified:
193/193, exit 0.

**Also fixed in the same file:** the PATCH loop ignored its own status code.
The verify block opens with *"A 204 is not a write — prove it landed"* and the
write it was proving was unchecked, so a PGRST204 or an auth failure returned
silently and the only symptom was the verify reporting 0/N — which reads as a
stamp problem, not a write problem. Now counted and reported.

Scanned for the same `[:10] == et_today()` pattern repo-wide: this was the
only instance.

### 🚨 P1 — AN UNENCODED `&` SILENTLY EATS WRITES, REPO-WIDE

Caught because the NCAAF backfill reported **"patched 571/571"** and the
read-back found **553**. The 18 missing rows were every fixture with an
ampersand in a team name: Texas A&M, North Carolina A&T, Florida A&M, Prairie
View A&M, East Texas A&M.

Unencoded, the `&` **terminates the query parameter**. The filter becomes
`game_id=eq.ncaaf_..._Texas A` plus a stray `M` param, the PATCH matches zero
rows, and PostgREST answers **204 — which reads as success**.

Proven, not inferred:

| id contains | unencoded | encoded |
|---|---|---|
| a space | **1 row** | 1 row |
| an ampersand | **0 rows** | 1 row |

So spaces are safe (`requests.requote_uri` normalises them) and the blast
radius is ids containing `&` — **NCAAB 461 ids (479 occurrences), NCAAF 18** —
*not* the 2,401 MLB ids containing spaces.

**This is live and not confined to my scripts.** 25+ existing scripts
interpolate a game_id into a filter on an `&`-bearing table without encoding,
including `ncaaf_mc_simulator`, `ncaaf_weather_pull`, `ncaaf_rankings_pull`,
`ncaaf_to_margin_pull`, `ncaaf_rz_kicking_pull`, `ncaaf_recruiting_pull`,
`recompute_ncaaf_primary_play`, `backfill_ncaaf_team_tendencies`,
`ncaab_mc_simulator`, `ncaab_panel_predictor`, `ncaab_resolve_primary_play`.

**Texas A&M is an SEC team that plays every week**, so its games are being
silently skipped by that whole set — enrichment never lands, and a read returns
zero rows rather than erroring. NCAAB's 461 ids matter from November.

`game_context.py` already does it correctly
(`requests.utils.quote(game_id)`), so the fix is to copy an existing pattern,
not invent one. **Not attempted tonight** — 25 files, each needing a call-site
edit plus verification, and the read paths fail differently from the write
paths (silently missing data vs a lost write). Scoped as its own pass.

Encoded tonight in the six scripts written during this work
(`backfill_ncaaf_game_flags`, `watchdog_market_sanity`, and verified

### 🚨 P1 (NEW) — the sport_registry client cache defeats backend control

Andy: *"i want complete control via backend when these notes populate what they
say and when they go down, dont like current cache process because some people
dont see the note all the time."* He is right, and this is the mechanism.

`app/index.tsx:6614`:

```js

  {ttlMs: 30 * 60 * 1000, staleWhileRevalidate: true});
```

Four consequences, all of which match the symptom:

1. **Up to a 30-minute lag** between a backend edit and any given user seeing
   it. A note taken down is still on screens for half an hour.
2. **Two users see different notes at the same moment**, depending where each
   sits in their own 30-minute window. There is no single truth on screen.
3. `staleWhileRevalidate: true` serves the OLD value while refetching — so the

4. **If the revalidate fails, the stale value persists indefinitely.** There is

**This is the wrong trade for this table.** `sport_registry` is **7 rows**. The
fetch is trivial; caching it for 30 minutes buys almost nothing and costs the
operator control of a user-facing disclaimer.

- **Do not cache it at all** (or `ttlMs` ≈ 60s). 7 rows, once per mount.
- **Key the cache on `updated_at`** — the column already exists on every row,

- Keep the TTL but drop `staleWhileRevalidate` for this key, so a user never

## NHL totals — issue #7 CLOSED with evidence: do not build it

Issue #7 was *"NHL `projected_total` ignores every input it has"* —
`(avg_gf+avg_ga home + same away)/2` and nothing else, while
`nhl_game_context` carries xGF/60, xGA/60, PP%, PK%, high-danger and goalie
SV%/GSAA, all populated 46/46. The obvious conclusion was "feed it the inputs".

**Measured instead of assumed, and the answer is no.**

Sample: 91 regular-season games (from `season_start` 2026-09-29, excluding the
preseason rows that `project_nhl_preseason_record_930` warns distort NHL
records) having every candidate input, a final score and a closing total.

    actual total   mean 6.21   sd 2.37
    MARKET         MAE 1.830   <-- the bar
    current model  MAE 1.839   bias -0.16

So the current model is **already level with the market** — it is not broken,
it is redundant. That is a different diagnosis from NFL's total, which IS
broken (a 30% anchor to BASE_TOTAL produces mechanical line-predictable leans).

### First attempt was worse, and the reason is instructive

A principled v2 — xG matchup scaled by the opposing goalie's save factor
`(1-SV)/(1-league SV)`, plus a back-to-back bump — came out at **MAE 2.384,
bias −0.91**, materially worse than doing nothing. The multiplier
**double-counts**: xG already encodes chance quality, so re-scaling it by save
performance applies the goalie twice. Its sd blew out to 1.72 against the
market's 0.38.

### The ceiling test, which settles it

Rather than hand-tune, fit the **best possible linear use** of the inputs
in-sample — optimistic by construction, since it is scored on the same rows it
is fitted on. If even that cannot beat the market, the information is not there.

| feature | MAE | R² | beats market? |
|---|---|---|---|
| xG matchup alone | 1.841 | **+0.000** | no |
| goalie SV sum | 1.843 | +0.003 | no |
| PP% + PK% | 1.845 | +0.004 | no |
| high-danger chances | 1.840 | +0.000 | no |
| 5v5 Corsi | 1.822 | +0.010 | nominally, by 0.008 |
| **all five together** | 1.834 | **+0.015** | no |

And the decision-relevant test — do they add anything **on top of** the line?

    market alone (refit)        MAE 1.832
    market + all five inputs    MAE 1.834     improvement -0.002

**The five unused inputs explain 1.5% of total variance in-sample and make the
market-based prediction slightly WORSE when added to it.** Out-of-sample value
is ≤ that, i.e. ~zero.

**Conclusion: do not rebuild the NHL total model around these inputs.** They are
real information about the *game* — exactly why they belong in the stat-surfacing
layout — and ~zero information about the *total*. This is the same split the
design doc argues for: show them to users, do not model with them.

Caveat stated plainly: n=91 is small, and R²≈0 does not prove no relationship
exists — it proves none is detectable at this sample. But "market + inputs" is
the right question and it answers no.

### What this re-prioritises

NHL totals move DOWN the list; **NFL's anchored total moves up**, because that
one has a measured defect (91% UNDER leans above a 47 total, 96% OVER below 41)
rather than a redundancy.

## "Isn't close to the market a good thing?" — yes, for one purpose, and it hides two different failures

Andy, on the NHL totals finding: *"Isn't the model being close to the market a
good thing in theory?"* Right question. The answer needs a decomposition.

    model = market + deviation

**Accuracy** comes almost entirely from the `market` term. **Profit** comes
only from the `deviation` term. So a model can be accurate *and* worthless at
the same time — good MAE inherited from the line, deviations that are noise.
MAE alone cannot tell those apart, which is why "our MAE is close to the
market's" is not reassurance.

### The test that separates them

Regress what the line MISSED on how much we DISAGREED with it:

    (actual_total − close_total)  ~  (projected_total − close_total)

slope ≈ 0 → our disagreements are noise · slope > 0 → they carry information ·
slope < 0 → they are systematically backwards.

| sport | n | model MAE | market MAE | our dev sd | slope | 95% CI | verdict |
|---|---|---|---|---|---|---|---|
| NHL | 105 | 1.911 | 1.795 | 0.72 | −0.034 | [−0.547, +0.448] | **NOISE** |
| NFL | 79 | 11.726 | 10.589 | 3.90 | **−0.908** | **[−1.553, −0.242]** | **ANTI-informative** |

### NHL = market + noise

MAE is respectable and the projection is unbiased, but it deviates from the
line with **sd 0.72, roughly twice the market's own 0.37**, and those
deviations are random (slope ~0, corr −0.011). Betting noise at −110 loses the
vig by construction. So the NHL total projection is **accurate enough to SHOW
and useless to BET** — exactly the "close to the market is good" intuition, and
exactly why it is not enough.

### NFL = an anchored constant, so its deviations are INVERTED

The NFL slope is **−0.908 with a CI that excludes zero** — the only totals
result all week to clear a CI, and it clears in the wrong direction. For every
point the model projects *above* the line, the total lands ~0.9 points *below*
it.

The mechanism is arithmetic, not mystery. `projected_total` is pinned near
44.5, so

    deviation = 44.5 − market

which is just the market's own level, negated. The market's level **is**
informative, so our deviation inherits that information with a minus sign.
That is why NFL totals are worse than NHL's: not noise, but a measurable
inversion.

**Do NOT read this as "bet the opposite".** That inference is the trap. Betting
against every lean means OVER on high totals and UNDER on low ones, and the
direction baselines already say there is no free lunch there: on the same test
set, always-OVER ran **−6.82%** and always-UNDER **−2.18%**. The slope says our
lean is wrong; it does not say its inverse is profitable.

### Path forward — NHL

1. **Keep the projection for display.** Unbiased, roughly market-accurate,
   fine to show a user.
2. **Stop emitting O/U leans from it.** Its disagreements are noise.
3. **A better model of the same inputs will not help** — the ceiling test put
   xG at R² +0.000 and all five inputs at +0.015, and they made a market-based
   prediction *worse* when added to it. The only credible NHL totals edge is
   **information the market lacks, not a better model of what it has**:
   confirmed-goalie timing and late scratches, i.e. a latency/ops edge, not a
   modelling one.
4. **Priority: low.** Spend the NHL effort on the stat-surfacing layout, where
   those same five inputs are genuinely valuable.

### Path forward — NFL

1. **The 30% BASE_TOTAL anchor has to go — but NOT in favour of a de-anchored
   matchup model.** That was tested and fails out of sample: leave-one-out
   −0.154 MAE, temporal split −1.949.
2. **Anchor to the MARKET instead of to 44.5.** Then
   `projected_total ≈ market + small adjustment`: honest for display, and it
   stops manufacturing a lean on 56 games. This is the minimal defensible fix
   and it removes the inversion at the source.
3. **Run `shadow_nfl_total_suppress` in parallel**, and promote on the stated
   bar — the alternative market the engine would have emitted doing better, not
   merely the suppressed picks losing.
4. **The one place NFL totals have measured information is WEATHER.**
   wind → UNDER is **55.6% on n=1,444**, the only validated totals lens we own,
   and `wind` is populated on **14 of 193** upcoming games. That is a bigger
   prize than any re-modelling, and it is blocked on `OPENWEATHER_API_KEY`.

### The general rule this gives us

For any model, report **three** numbers, never just the first:

1. MAE vs the market — are we accurate?
2. sd of our deviation — do we disagree at all?
3. **slope of the residual on that deviation — is the disagreement worth
   anything?**

A model that scores well on (1), moves on (2) and flunks (3) is the most
dangerous shape we can ship, because it looks healthy on every dashboard while
every pick it generates is noise or worse.

## The rolling-form voter — 12 tests, 2 invalid, 9 noise, 1 real

Andy's engine vision lists "rolling live stats" as a panelist. We had 88
`team_form` signals that READ rolling stats and **no equation turning rolling
form into a projected score**. `build_rolling_voter.py` builds one for all six
sports from `feature_history` (pf_pg, pa_pg, last3/last5 margin, last5_total,
avg_total — leak-free and walk-forward), fits on a TRAIN slice and scores on a
TEST slice by time.

Every model reports three numbers, because NFL's existing total passes on MAE
alone and is anti-informative: **MAE vs market · sd of our deviation · slope of
the residual on that deviation.**

### Two results thrown out — my baseline was wrong

MLB and NHL **spread** came back "INFORMATIVE" with slopes of +0.68 to +1.11
and CIs clearing zero. **Both are invalid.** I used `close_spread` /
`close_puckline` as the market's margin estimate, and measured:

| sport | column | distinct values | sd |
|---|---|---|---|
| NFL | close_spread | 58 | 5.68 |
| NCAAF | close_spread | 130 | 18.88 |
| NBA | close_spread | 66 | 7.70 |
| NCAAB | close_spread | 590 | 10.33 |
| **MLB** | close_spread | **5** | 1.65 |
| **NHL** | **close_puckline** | **2** | 1.45 |

MLB's run line and NHL's puck line are **fixed handicaps (±1.5)**, not margin
forecasts. Regressing against a near-constant just measures "does the model
predict the margin at all" — true, and nothing to do with beating the market.
A proper MLB/NHL margin baseline has to come from the **moneyline** converted
to an implied margin. Not attempted here.

### The nine that are noise

NFL, NCAAF, NBA and NCAAB **spread** (the four sports with real point spreads):
all noise. NFL, NCAAF, MLB, NBA, NCAAB **total**: all noise. Consistent with
everything else measured this week.

### The one survivor: NHL TOTAL

| model | MAE | dev sd | slope | 95% CI | verdict |
|---|---|---|---|---|---|
| market (as-is) | 1.790 | — | — | — | — |
| rolling form alone | 1.795 | 0.367 | **+0.567** | **[+0.202, +0.900]** | informative |
| market + rolling form | 1.791 | 0.257 | **+0.817** | **[+0.302, +1.302]** | informative |

n = 1,067 test games, temporal split at 2025-11-22, valid market baseline.
**The first CI-clearing, out-of-sample, correctly-baselined result all week.**

**And it does not contradict the earlier "NHL totals inputs are worthless"
finding — it corrects the power of it.** That test used xG, goalie SV, PP/PK and
high-danger on **n=91** current-season games. This uses a *different input
family* (recent scoring form) on **n=2,666** across three seasons. The earlier
conclusion was right about those inputs and under-powered in general; building
`feature_history` is what made the better test possible.

### The caveat that decides whether it is tradeable

**The informative deviation is small.** sd 0.26–0.37 goals of disagreement on a
6.2-goal total, and MAE barely moves (1.790 → 1.791). A +0.8 slope on a
0.26-goal deviation only pays when the deviation actually crosses the posted
line, which on a market that trades 5.5/6.0/6.5 will be uncommon.

So the honest status is **"real signal, unproven as a bet"** — exactly the case
for a shadow rather than a wire. Next step is to convert it to a side and
threshold and grade THAT (a slope is not a betting rule), with the direction
control, before anything is wired.

### What this says about the voter programme

The rolling panelist is **worth having in one of twelve places**, which is a
useful answer: it is not a general-purpose voter, and wiring it everywhere
"because the engine should have a rolling model" would add noise to eleven
markets to capture one. Independence is necessary but not sufficient — a new
panelist still has to be *right* somewhere.

## The panel is one analyst in several hats

Andy's engine design has the models as a board of GameDay panelists — each with
their own data, their own take, each making a pick, the engine weighing what
the panel concludes. Built the two pieces that were missing and measured
whether we have it.

### Correction to the first scorecard

The first run reported NFL `mc`, NFL `panel`, NCAAF `mc` and NHL `panel` as
panelists that "never make a pick." **That was a read bug.** I declared
panelists by guessing column names: `mc_expected_margin` is not a column (it is
inside the `mc_probabilities` jsonb blob, sd 7.686 across 102 distinct values),
`panel_pred_spread` is not a column (panel has `panel_pred_home_pts` /
`panel_pred_away_pts`), and NHL has no `panel_pred_total` at all. `.get()`
returned None, every row was skipped, and "this model has no opinion" got
published about models that have one on every game.

Corrected: NFL mc 59 picks 50.8%, NFL panel 52 picks 51.9%, NCAAF mc 256 picks
52.0%. **No panelist in any sport is silent.** Guard added: 0 readable rows is
now a WIRING ERROR with a non-zero exit, never a record.

### The real finding: 27 duplicate pairs

`audit_panelist_independence.py` measures how often each pair takes the **same
side of the posted line** — side agreement, not deviation correlation, because
two models can correlate +0.9 in deviation and still split on the side, and the
side is what gets bet.

| market | agreement |
|---|---|
| NHL total | goals/mc/projected — **all three pairs 100.0%** |
| NCAAF total | all 6 pairs **99.5–100%** |
| NFL total | projected vs v3 **98.4%**, model vs projected **100%** |
| NFL margin | projected vs v3 **100%**, panel vs v4 **96.9%** |
| NCAAF margin | projected vs sp_plus **98.8%**, mc vs both **99.6%** |

Five or six nameplates, usually **one opinion**. Requiring two panelists to
agree is **free** when they are the same number — which is why consensus
signals have never earned their keep.

Distinct voices, the only ones that may count as separate votes: NFL margin
only `mc`; NFL total `mc` and `panel`; NCAAF margin only `epa`; NCAAF total
**nothing**.

Caveat: the bloc rollup is transitive and can overstate — NCAAF margin prints
"5 nameplates, 1 voice" but epa vs projected is genuinely 50.7%, pulled in only
through `model`. The per-pair numbers are the evidence.
