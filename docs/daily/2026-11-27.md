## NCAAB matchup history: the measurement, and why it cannot be made yet

This is the open item from 11-26 — can the nine NCAAB `h2h_*` signals earn a
real weight instead of riding `recommended_weight` 0.30? They are all
UNVALIDATED at n in {0, 2, 6}.

**New: `measure_h2h_matchup_history.py`.** It does not read the
`h2h_last5_*` context columns at all — it derives matchup history from the
results table, taking for each game the prior meetings between those two
teams strictly before that game's date. Walk-forward by construction: a
future game cannot have an earlier date, so there is no "as of" bookkeeping
to get wrong. It tests the EXTREME cells the signals actually name (4-5 and
0-1 of the last 5), not a median split, which was the error in the
11-25 pass — a median split lumps 0-2 against 3-5 and discards the
dominance the signals are about.

### Why the context columns could never have measured this

```
ncaab_game_context    1,195 rows, ALL dated 2026-11-01 or later
                      h2h_last5_games_played >= 3 on TWENTY-ONE rows
ncaab_game_results   12,793 settled games back to 2024-11-04
```

The `h2h_last5_*` columns live on the context table, which only covers this
season. A signal keyed on them can never accumulate a sample. The history
was in the results table the whole time.

### Deriving it from results gives 1,270 eligible games — and 18 usable

```
eligible games (>=3 prior meetings): 1,270 of 12,793
pairs that have ever met: 7,038

season     eligible    ATS  total  ML pair  usable
2024-25           2      2      2        2  OK
2025-26       1,235      0      0        0  UNUSABLE -- no stored market
2026-27          33     16     16       16  OK
```

**The entire 2025-26 NCAAB season — all 5,521 games — has zero closing
spreads, zero totals, zero moneylines, zero graded ATS and zero graded
totals. Scores only.** And that is precisely the season carrying **1,235 of
the 1,270 (97%)** eligible matchup-history games.

That is arithmetic, not coincidence: matchup history only accumulates with
time, so eligible games pile up in the latest seasons. The one season with
enough accumulated history is the one with no market to grade against. 2024-25
had the prices but not yet the history; 2026-27 has both but is 26 days old.

So the honest answer on NCAAB h2h is **not** "no edge" and **not** "nobody
measured it". It is: the measurable sample is **18 games**, and no verdict
is issued below n=30. The strongest cell available is
`h2h_under_streak` at n=12, +5.6pp over its direction-only control,
**+0.32 SE** — noise, and labelled as such.

**Matchup history predicts winners. It does not beat the close.**


`h2h_away_dominant` posts **+3.79 SE against a direction-only control** —
and that is exactly what the control exists to expose. The away side does
win 50.6% against a 40.8% baseline; the market has already priced it at
52.1%. The signal finds the better team, not a mispricing.

`h2h_under_streak` clears the −110 breakeven by +4.3pp, but beats its own
direction control by only **+0.7pp (+0.30 SE)** — the gain is the sample's
mild under lean, not the h2h condition.

The one thing worth watching is `h2h_over_streak`: 65.4% on n=26, +1.76 SE.
Under the n≥30 bar, so no verdict. It will cross 30 during conference play.

This does not undercut the method. MLB's `pitcher_vs_team_*` is a specific
pitcher against a specific lineup; NCAAB's is a team-level win count, and
the close absorbs that.

### The cells are not equally reachable

A "4-5 of last 5" cell cannot fire on a 3-game window; a "0-1 of 5" cell
can. `h2h_home_dominant` fires on a mean window of 4.31 (full on 31%);
`h2h_away_dominant` on 3.15 (full on **1%**). So the away cell's n is 12x
larger from window length alone, and what it really fires on is "the home
team lost 2-3 of the last THREE". The production signal reads
`h2h_last5_home_wins`, a raw count, so it carries the same asymmetry.

### CORRECTION: it is seasonal, and the writer was never broken

I wrote above that the context columns are "structurally unable" to feed a
measurement and that the signals should be rewired to read results. **The
second half was wrong.** `enrich_team_form_universal.compute_h2h` already
queries the RESULTS table with `game_date lt.<game_date>` and no season
bound — it looks back across seasons correctly. The gap is measurement
(context rows exist only for current/upcoming games), not firing.

The real reason the registry shows n in {0, 2, 6} is the **calendar**:

```
2025-11  0.1%     2026-01  15.6%     2026-03  53.2%
2025-12  2.7%     2026-02  51.4%     2026-11  2.4%  <- today
```

November is non-conference, so pairs have not met. The refit's default
`--days 90`, run today, measures a condition that fires on 2.4% of the
slate. **By February it fires on more than half the board** — so an
unmeasured 0.30 prior is about to go live at scale in roughly two months.
That is the actionable risk, and now there is a measurement to set it with.

Note also that `--days 90` means the recovered 2025-26 season does **not**
reach the registry on the scheduled refit; it reaches this measurement,
which has no window. A wider refit would see it, and that is a separate
decision with its own cross-season hazards.

## A real defect found on the way, and a non-defect I nearly shipped

`refit_signal_registry._american_to_be` guarded only `== 0`, so a value
**inside ±100** was converted as if it were American odds. There is no such
price. 333 of 4,987 priced 2024-25 pairs (6.7%) carry one — `-125 / 60`,
`-81 / -116`, `15 / -121`, seven literal zeros. A stored `-81` became a
**44.75% breakeven: a favourite below a coin flip** — a bar pushed DOWN,
crediting edge that was never there. It feeds `price_breakeven_pct` and,
since 11-25, the live `edge_weight` bar. Fixed; returns None, which the one
caller already treats as "no price for this firing". Pinned by
`test_american_odds_guard.py` (11 guard suites, all green offline).

The live puller was already correct — `ncaab_odds_pull._consensus_ml` takes
an actually-quoted price rather than a mean of quotes, which is why 2026-27
has **zero** incoherent pairs. This is a historical-data defence.

**And the one I nearly got wrong:** I called the 452 rows past ±5000 (out
to `-100000 / +3300`) placeholders, and started writing a reject for them
into that same path. All 452 have a coherent overround (1.01–1.06), sit on
a mean **26.6-point** closing spread, and the favourite won **450 of 452**.
They are real prices for real mismatches. The reject would have stripped
out exactly the prices a favourite signal cannot beat, flattering every one
of them — cherry-picking in the direction that manufactures edge. It did
not ship, and the test now pins that they stay in.

Earlier the same session I also called 238 both-negative moneyline pairs
impossible, from the sign alone; `-109/-110` is a 1.045 overround, an
ordinary pickem. **Sign and size are both the wrong test. Overround is the
test.**
