### The engine, fixed

The pooling was the bug and it was never NCAAB-only. `_load_registry` has
said since 2026-09-24 that `market_scope` "is part of the table's real
unique key" and then worked around it by keeping the larger sample — its own
example being MLB `long_rest_home_ats`, VALIDATED on `spread` and
UNVALIDATED on `rl`, "a 0.5-vs-0.0 weight decided by row order". **106 of
1054** (name, sport) pairs carry more than one scope.

Four changes to make a split computable *and* writable:

- `_load_registry` keys `(name, sport, scope)` and keeps the old
  `(name, sport)` entry, so nothing that resolved before stops resolving
- `_resolve_weight` asks for the source row's own `market_scope` first
- the collectors tally right/wrong, the control and the breakeven **per
  market**; `merge_firings` carries `by_mkt` — the third key added to those
  collectors, and its docstring's warning is about dropping exactly this
- **`upsert_registry` keyed its id map on (name, sport), last-row-wins.**
  Two rows for one signal would both PATCH the same id, the second
  overwriting the first. The split was *unwritable* until that key included
  the scope.

`build_rows` now emits one row per market a signal fired `min_n` times in,
and sets `market_scope` from the dominant market otherwise, where INSERTs
previously left it NULL.

**Verified no-op where it should be:** over all 587 enabled
`signal_sources`, the new lookup returns a byte-identical
`(hit_rate, n, tier)` on **587 of 587**. (My first impact script reported 14
changes; that was my error — it failed to emulate the inline `hit_rate_pct`
path, which short-circuits before any registry lookup. The registry was
correct all along.) I also checked whether a specific scope should be
blocked from falling back to another scope's row, and left it alone on
measurement: only 5 enabled rows do it, all MLB prop signals generalising
`pitcher`/`hits` → `prop`, which is intentional.

**The result.** `OFF_RATING_GAP` was about to take the maximum weight 1.0 on

NCAAB's measured, control-judged signals went **2 → 12**, each storing its
