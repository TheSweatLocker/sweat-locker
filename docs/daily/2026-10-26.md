## The method lesson, which matters more than the finding

**Walk-forward validation cannot detect a leaked FEATURE.** It guards
threshold choice against the future. If the input contains the outcome, every
period is contaminated equally and the harness prints `STABLE EDGE` — which
it did, on every contaminated cut, with a monotonic ladder and a symmetric
control. Stability is the leak's *signature* here, not evidence against it.

The two checks that do work:
1. **Era-split on the fix date.** A fix bounds new writes; it almost never
   repairs stored ones.
2. **Rebuild the feature from raw components and re-run.** The gap between
   stored-feature and rebuilt-feature results *is* the leak, measured.

Cheapest tell, checkable in one query: **does the edge grow as the price gets
cheaper?** Leaky ran +5.3 at ≤−250 up to +22.0 at ≥−110. Rebuilt is flat
(−2.5 / −4.4 / −6.5 / −1.9 / −0.4). Real skill does not scale inversely with
market confidence.

Saved as `feedback_walk_forward_misses_feature_leak`.

## Built: `repair_leaked_prop_lookback.py`

Repairs the stored values in place, no API calls, dry-run by default.

- **13,290 MLB rows to repair**, median L5 change 11.1%, p90 100%, max 950%
- Every original preserved under `signals._leak_repair`, so `--revert` walks
  it back from the row itself
- **Two honesty guards:** `_stat_avg_season` is NULLED, never repaired (MLB
  computed it from 30 values, only 10 were stored — unrecoverable); L10 is
  only rewritten when 10 bounded entries survive, which in practice is never,
  since the store is capped at 10 and dropping any entry leaves 9
- The surviving window is not discarded — it is relabelled `_stat_avg_recent`
  + `_stat_recent_n`, so a consumer gets a short-window average carrying its
  own n instead of a last-8 wearing an L10 label
- **Batched writes**: ~270 requests at CHUNK=50, not 13,290 PATCHes. B154
  exists because 214k requests/day took the app down for paying users.
  Asserts all payload objects share one key set first, because a ragged batch
  upsert nulls columns it never names
- Re-reads a repaired row after writing and fails if the marker is absent —
  a green step may write nothing
