## 🚨 I TOOK THE APP DOWN FOR ~30 MINUTES. ROOT CAUSE AND FIX.

Andy, live: "the app isnt working right now, says somehting went wrong" →
"Objects are not valid as a react child. Found object with keys (total,
source)".

Those are `set_potd_manual.py`'s own keys. It writes

    'score': {'total': a.score, 'source': 'manual'}

The `{total, source}` SHAPE is fine — 10-31 shipped
`{"total": 81, "source": "jerry_conviction"}` and rendered. What broke is
**`total: null`**, which happens on every run of that script that omits
`--score`. I omitted it deliberately: that flag feeds `sweat_score`, a
projection-vs-close magnitude, and inventing a 74 for a hand-set pick would
claim a number it never earned. The client falls back to rendering the whole
object when the number is missing, and an object as a React child is a hard
crash, not a blank field.

Fix: the key is written **only when there is a real number for it**.
2026-10-27, -28 and -29 carried no `score` key at all and rendered fine —
that is the shape now emitted.

**The lesson, and it is mine:** a manual path must emit a payload shape the
app has already rendered. *Present-but-null is a different shape from
absent*, and I reasoned about what the field MEANS without checking what the
client DOES with it.
