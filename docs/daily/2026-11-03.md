## 1. Mode derivation moved off the run-time clock (5 workflows)

`ncaab`, `ncaaf`, `nfl`, `ufc` pipelines and `daily_card` all dispatched on
`HOUR=$(date -u +%H)` matched against the hours their crons are SET to. With
7-10h lateness the hour at run time is not the cron that fired, so every slot
landed in the wrong bucket non-deterministically. All five now `case` on
`github.event.schedule`, the cron expression that actually fired.

Validated: every cron string keyed in a `case` is one the workflow declares,
and every fall-through to the `full` default is intentional. A typo would
silently fall through, which is the same defect class being fixed, so this is
checked mechanically rather than by eye.

| workflow | keyed | declared | unmapped (-> full) |
|---|---|---|---|
| ncaab_pipeline | 3 | 4 | `0 14 * * *` |
| ncaaf_pipeline | 4 | 6 | `0 15 * * 2`, `0 22 * * 3` |
| nfl_pipeline | 4 | 9 | 5 full-run slots |
| ufc_pipeline | 3 | 4 | `0 14 * * 4` (Thu full pull) |
| daily_card | 3 | 3 | — |

`daily_card`'s model scorecard was gated `HOUR = 05 or 06` and so had stopped
running entirely; now keyed on `'0 5 * * *'`.

## 2. The card now rebuilds when a sport pipeline FINISHES

Crons cannot fix the ordering: lateness is 7-10h, varies run to run, and is
growing. `daily_card` gains a `workflow_run` trigger on **NBA Pipeline
Daily**, **NHL Pipeline Daily**, **NCAAB Pipeline Daily** and **Nightly
Cross-Sport** (`types: [completed]`), which is event-driven and immune.

Safe because the card already builds 3x a day — another build is not a new
risk class — and `concurrency: daily-card` with `cancel-in-progress: false`
serialises the burst rather than letting two runs write the same tables (the
2026-09-18 defect). The heartbeat now labels these runs
`after:<triggering workflow>` so the ordering stays auditable.

## 3. THE PANEL MODEL HAD TWO BUGS, AND THE MODE FIX ALONE WOULD NOT HAVE FIXED IT

Chasing the dead `ncaab_rating_snapshots` found that the three rating
scrapers each derived the season **differently**, and two were wrong:

| script | derivation | wrote on 2026-11-03 |
|---|---|---|
| `ncaab_torvik_pull.py` | `--season default='2025-26'` hardcoded | **`2025-26`** WRONG |
| `ncaab_kenpom_snapshot.py` | `now.year if m>=11 else (now.year if m<=6 else now.year)` | **`2025-26`** WRONG |
| `ncaab_haslam_pull.py` | own logic, NOVEMBER rollover | `2026-27` right, but files Aug-Oct preseason under the finished season |

The kenpom one is a three-branch conditional that returns `now.year` in
**every branch** — the month test did nothing, so the season never rolled.
`ncaab_season.py` was written 2026-10-21 to be the single derivation and
killed this in five other places; all three of these were missed.

`ncaab_rating_snapshots` keys on `(snapshot_date, team, season,
rating_system)`, so with haslam on `2026-27` and the others on `2025-26`
there was **never more than one system on one key** — and the Panel needs 2+.
It could not fire for any team on any date, which is why the table read
haslam-only.

All three now call `ncaab_season.season_label()` / `season_end_year()`. Ran
them: 365 teams each, all under `2026-27`. Result on `(2026-11-03, 2026-27)`:

    teams with 2+ rating systems (Panel minimum):  363   (was 0)
    teams with all 3 systems:                      240
