## WHY A NEGATIVE-EDGE PLAY BECAME THE POTD: A TIER NO GATE HAD HEARD OF

`apply_stored_edge_cap` is the chokepoint that caps a bettable tier whose own
stored edge is non-positive. It read:

    t = str(pp.get('tier') or '').upper()
    if t not in ('PRIME', 'STRONG', 'LEAN'):
        return pp

The pick's tier is **`SOLID`**. Source: `jerry_anchor_potd._conviction_tier()`
mapped conviction **60-69 -> "solid"**, a word that appears nowhere else in
the system —

    _DG_TIER_RANK           PASS SKIP LIGHT COVERAGE LEAN STRONG PRIME
    publishable set         ('PRIME','STRONG','LEAN')
    lock_publish docstring  "PRIME / STRONG / LEAN / COVERAGE / SKIP / PASS"

and it is passed straight into `lock_publish`, whose locked tier **a DB
trigger reverts `primary_play.tier` to**. So a display label became the gating
tier of a live pick, and the EV gate waved it through.

**Exactly TWO rows in the entire database have ever carried `tier='SOLID'`,
and both are POTDs with negative model edge:**

| date | pick | edge |
|---|---|---|
| 2026-11-03 | Montreal Canadiens ML | **-2.96pp** (live when found) |
| 2026-11-02 | Houston Rockets ML | **-6.33pp** |

It only ever bit non-MLB, because only non-MLB conviction lands in 60-69 —
MLB POTDs ran 70-95 and got `strong`/`prime`, which the gate knows
(`project_conviction_is_a_baseball_scale_1027`). **The day the POTD went
cross-sport it began bypassing the EV gate silently.**

### Fixed

- `_conviction_tier`: 60-69 now returns `lean` (below the 70 STRONG threshold
  it already used — no threshold moved, it just stops inventing vocabulary).
- `apply_stored_edge_cap`: inverted to a NON-bettable list
  (`'', COVERAGE, PASS, SKIP, LIGHT`) so it **fails CLOSED** — an
  unrecognised tier is capped, not exempted.
- `_DG_TIER_RANK`: `SOLID` ranked with LEAN, since the publish-lock trigger
  has frozen it into already-locked rows.

**Replayed over 1,539 live `primary_play` rows, before vs after: exactly 2
outcomes change — the two SOLID POTDs. Zero collateral.**
